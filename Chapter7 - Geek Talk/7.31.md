# ReAct + 领域专家级 workflow 也许是现阶段 Agent 最佳实践
最近看了几篇 APM 或者业务侧使用 Agent 的文章/案例：
https://mp.weixin.qq.com/s/AZ-np48XJLM1QO5NJ_YiVA
https://mp.weixin.qq.com/s/n_UtUCGbOF-uKphybpi9Fg

无论是 REA、得物 troubleshooter，还是 crashlytics‑slack‑bot，它们并未在底层 Agent 范式层面做出创新性设计，核心价值集中在 LLM/Agent 的工程化落地与领域问题上的落地（或者叫适配），整体架构可以概括为：ReAct + 专家经验 + 准入/准出标准设计。

这里所说的专家经验，并非 “某个寄存器异常去哪里排查” 这类细粒度排错结论，而是一套 high level 层的 workflow，不涉及具体问题的细节解法。也不适合针对特定的、具体的、细节的问题去设计答案和解法，因为这些能力刚好是 LLM 海量数据训练后所产生的、跃迁般的“智能”，所以不用陷入细节，工程、代码层面也做不到。

ReAct loop：观察 - 思考 - 规划 - 执行，持续循环，再由独立 SubAgent 持续观察、衡量是不是达到一个可交付的状态，此时 loop 停止，达到准出标准，产出交付物。LLM 本身不算智能，海量数据训练后才产生超出预期的能力，觉得大有可为。Agent + 领域问题专家级的 workflow 结合 LLM 能力，也许是现阶段的最佳实践
